# Physical robot hardware adapters

## IMX500 QR inventory camera

The workflow app runs in the ROS 2 container. Raspberry Pi's camera stack runs on Raspberry Pi OS, so the app connects to the host service at `127.0.0.1:9011`. The hardware profile uses host networking. Inventory steps decode every QR code visible in one camera pass; codes in the upper half of the frame are assigned to shelf level 2 and codes in the lower half to level 1.

Install the camera service once on Raspberry Pi OS from the robot repository:

```bash
bash scripts/install_imx500_camera_service.sh
```

The installer enables `libot-imx500-camera.service` at boot and starts it immediately. After this one-time setup, do not launch the scanner manually for each robot session. The service runs on Raspberry Pi OS, outside the ROS container, because Picamera2 uses the host camera stack. It owns one camera session and shares captured frames between QR decoding, legacy barcode recognition, and the realtime MJPEG feed. Preflight checks that the service and camera are available; a `SCAN` step automatically starts camera capture on its first frame request. A bookshelf inventory step requests a bounded multi-QR scan and ends after no new QR has appeared for 0.75 seconds or the 30-second limit is reached. The upper/lower assignment uses the detected QR center against the image midpoint; keep the camera aimed straight at a shelf so both levels are in frame. No visible QR is a valid empty scan, while camera failures return an error.

The installer creates a random stream token in `/etc/libot/imx500-camera.env` and prints it once. Set the printed value as `RobotRuntimes__real__CameraStreamToken` in the backend configuration so the map camera stream can be viewed.

Configure the backend with the robot camera port and the same token:

```dotenv
RobotRuntimes__real__CameraStreamPort=9012
RobotRuntimes__real__CameraStreamToken=replace-with-a-long-random-token
```

The mapping page loads `GET /api/robot-runtimes/real/camera/stream` from the backend. The backend proxies the camera feed, so the browser never needs the Raspberry Pi address or camera token. Allow TCP port `9012` only from the backend machine.

Check the host camera with `rpicam-hello --list-cameras`. Keep scanner port `9011` bound to loopback; the ROS container uses host networking to reach it. Port `9012` must be reachable from the backend and should be protected with the stream token and a firewall rule.

## Touchscreen and speaker

The hardware image installs Tk and eSpeak. Compose mounts `/tmp/.X11-unix`, forwards `DISPLAY`, and maps `/dev/snd` into the container. In the active Raspberry Pi desktop session, allow the container's root user to use the display before starting the profile:

```bash
xhost +SI:localuser:root
docker compose -f docker/compose.yaml --profile hardware up -d --build
```

Workflow preflight opens a temporary Tk window and checks the Nav2 action server and eSpeak executable before dispatch. Touch buttons on the fullscreen UI submit the waiting workflow event directly to the active execution.
