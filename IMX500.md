# Physical robot hardware adapters

## IMX500 barcode camera

The workflow app runs in the ROS 2 container. Raspberry Pi's camera stack runs on Raspberry Pi OS, so the app connects to the host service at `127.0.0.1:9011`. The hardware profile uses host networking.

Install the camera and barcode packages on Raspberry Pi OS, then start the service from the robot repository:

```bash
sudo apt update
sudo apt install -y python3-picamera2 python3-pil python3-pyzbar libzbar0
export LIBOT_CAMERA_STREAM_TOKEN='replace-with-a-long-random-token'
python3 robot_app/hardware/imx500_scanner_server.py \
  --host 127.0.0.1 --port 9011 \
  --stream-host 0.0.0.0 --stream-port 9012
```

Leave that process running before dispatching a physical workflow. It owns one camera session and shares the captured frames between barcode recognition and the realtime MJPEG feed, so viewing the camera does not block a `SCAN` step. Preflight sends a `ping` to the service, and each `SCAN` step requests a bounded camera scan. The adapter returns `scanned`, `timeout`, or `error`; it does not report a timeout as a successful scan.

Configure the backend with the robot camera port and the same token:

```dotenv
RobotRuntimes__real__CameraStreamPort=9012
RobotRuntimes__real__CameraStreamToken=replace-with-a-long-random-token
```

The mapping page loads `GET /api/robot-runtimes/real/camera/stream` from the backend. The backend proxies the camera feed, so the browser never needs the Raspberry Pi address or camera token. Allow TCP port `9012` only from the backend machine.

Check the host camera with `rpicam-hello --list-cameras`. Keep the barcode scanner port `9011` bound to loopback; the ROS container uses host networking to reach it. Port `9012` must be reachable from the backend and should be protected with the stream token and a firewall rule.

## Touchscreen and speaker

The hardware image installs Tk and eSpeak. Compose mounts `/tmp/.X11-unix`, forwards `DISPLAY`, and maps `/dev/snd` into the container. In the active Raspberry Pi desktop session, allow the container's root user to use the display before starting the profile:

```bash
xhost +SI:localuser:root
docker compose -f docker/compose.yaml --profile hardware up -d --build
```

Workflow preflight opens a temporary Tk window and checks the Nav2 action server and eSpeak executable before dispatch. Touch buttons on the fullscreen UI submit the waiting workflow event directly to the active execution.
